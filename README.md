# Aequi

OpenAI 兼容的 LLM 代理网关：把多家上游统一到一个入口，按积分计费，自带管理面板。

任何按 OpenAI 协议写的客户端、SDK、插件，把 `base_url` 指过来就能用。

## 能做什么

### 一个入口，接多家上游

对外只提供 OpenAI 协议的两个接口：

- `POST /v1/chat/completions` —— 对话（流式与非流式），支持多模态与工具调用
- `POST /v1/images/generations` —— 生图

上游可以是 OpenAI、Google（Gemini）或 Anthropic 三种格式中的任意一种，
客户端不需要知道背后是谁，也不用为不同的上游改代码。

### 上游按「块」组织

一个**块**就是一家上游：一个地址、一种格式、一组密钥、一份模型清单。
同一个模型可以同时由多个块提供，按权重分流——某个块出问题，其它块照常服务。
也可以给块起个 id，让模型名带上它（`块id/模型名`）来指定走哪个块。

### 密钥自动避让，不用人盯着

- **上游说密钥不行**（401/403）连续 3 次才自动停用，并记下原因
- **被限流（429）、上游故障（5xx、网络抖动）只做退避**——优先听上游 `Retry-After`，没给就按 10 → 15 → 30 秒阶梯退避（30 秒封顶）；**永远不会因此停用**
- 任何一次成功立刻清零计数、恢复可用；退避到期自动回到队伍
- 每把密钥都能设「**永不暂停**」，彻底免掉自动停用（手动暂停/恢复、手动测试不受影响）
- 面板里可以随时暂停、恢复、测试密钥（测试不消耗 token）

### 并发可控，超了就排队

每个块能设并发上限。达到上限后新请求**排队等待**（先到先服务），而不是被拒绝；
排队超过 30 秒才返回「上游通道繁忙」并告知客户端——目的是别把上游打爆，不是把人挡在门外。
对话、流式、生图共用同一道闸门。

管理面板实时显示每个块的**在飞数**与**排队数**，5 秒刷新一次。

### 积分计费

- 1 积分 = 10000 最小单位；按模型倍率折算（1.0 倍时 1 token = 1 最小单位），精度 0.01
- 倍率挂在「块 + 模型」上，所以同一个模型在不同块可以卖不同的价
- 1000 token、倍率 1.5 → 扣 1500 最小单位 = **0.15 积分**
- 零头向上取整，有消耗就至少记 1 个最小单位——不会被抹成 0
- 扣费与记账在同一事务里原子完成，不会透支
- **余额不足不会让请求失败**：扣除剩余全部积分、余额清零，用量照记、响应照常返回
- 可以给访问密钥设「无限额度」，跳过余额判断但照常记账

### 用量与日志看得见

- 输入 / 输出 / 缓存命中的 token 分开记录
- 上游不报用量时按本地估算，并在记录里标记「估算」
- **管理员**能看到完整请求日志：走了哪个块、用的哪把上游密钥、客户端 IP 与 UA、上游返回的原话
- **密钥持有者**只看得到自己的用量与脱敏后的错误（统一显示「上游响应异常」，不泄露上游地址与报错原文）
- 日志默认保留 7 天，可在 1–365 天之间调整；用量与日志都支持向前翻页

### 管理面板

内嵌在服务里，浏览器直接打开：

- 账号密码 + TOTP 两步验证登录，可查看和管理登录设备
- 上游块管理：地址、密钥、模型清单、并发上限、计费倍率、自定义请求头、模型级额外参数
- 访问密钥签发与管理：额度、可用模型、用量视图
- 请求日志与用量查询

## 快速开始

```bash
# 1. 首次启动，用环境变量初始化管理员账号（仅在控制面数据库不存在时读取）
#    源码构建方式见文末，也可以直接用下方 Docker 一条命令起服务
AEQUI_ADMIN_USERNAME=admin AEQUI_ADMIN_PASSWORD=改成随机值 ./target/release/aequi

# 2. 打开面板 http://localhost:8080，登录后新建一个上游块：
#    填上游地址与密钥、选择格式、添加模型并设置倍率
# 3. 在面板里签发一把访问密钥（可设额度与可用模型）

# 4. 客户端把 base_url 指过来即可
curl http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer <访问密钥>" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4o", "messages": [{"role": "user", "content": "你好"}]}'
```

## 运行

```bash
# 无参启动即为服务模式（默认监听 0.0.0.0:8080）
./target/release/aequi

# 把密码重置为新的随机值并打印一次
./target/release/aequi reset-password

# 关闭两步验证（验证器丢失时的自救途径）
./target/release/aequi disable-otp
```

- 没有配置文件：后台设置存在数据库里，首次启动写入默认值，之后以数据库为准（面板里可改）
- 数据库默认放在工作目录：`aequi.db`（账号、会话、设置）与 `aequi-data.db`（密钥、用量、上游、日志）

### 环境变量

| 变量 | 说明 |
| --- | --- |
| `AEQUI_DATABASE_PATH` | 控制面数据库路径（账号、会话、设置） |
| `AEQUI_DATA_DATABASE_PATH` | 数据面数据库路径（密钥、用量、上游、日志） |
| `AEQUI_ADMIN_USERNAME` / `AEQUI_ADMIN_PASSWORD` | 首次启动的管理员账号，仅在控制面数据库不存在时读取 |

## Docker

```bash
docker run -d -p 8080:8080 -v aequi-data:/data \
  -e AEQUI_ADMIN_USERNAME=admin -e AEQUI_ADMIN_PASSWORD=改成随机值 \
  ghcr.io/<owner>/aequi:latest
```

镜像基于 alpine（无头精简系统）+ musl 静态二进制，约 20 MB；非 root 用户运行，
`/data` 挂卷即持久化，带健康检查。推 tag 时自动构建发布 amd64 / arm64 镜像。

## 已知边界

- 流式对话（`stream: true`）对三家上游都已支持；生图接口不支持流式
- 每个块目前只支持一个上游地址（多地址轮询未实现）

## 开发

面板源码在项目外的 `../Aequi-web`（React 19 + Vite），构建产物复制进后端 `web/` 目录后由 rust-embed 嵌入：

```bash
cd ../Aequi-web && npm install && npm run build && cp -r dist/* ../Aequi/web/
cd ../Aequi && cargo build --release
```

跳过前端构建也能编译（会兜底创建空的 `web/` 目录，运行时显示「控制台尚未构建」提示页）。

```bash
cargo test              # 单元 + 集成测试
cargo check --all-targets --locked   # CI 同款检查范围
```

CI 三条流水线（测试、多架构二进制发布、Docker 镜像）在推送与打 tag 时触发，均以测试通过为前置门槛。
